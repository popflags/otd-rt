### Analog Pen: button 1 presses no longer cut holds

From the first CP923 gameplay session (Windows, 2026-10-20, Activation Distance 1000, Analog Pen on).

- With **Analog Pen** and **Firmware Sample Clock** on, a report gap the clock sees (the pen re-tuning for a side button) now starts
  the Button Settle window too, not only the change of the button bits. Pressing button 1 while holding pulls the pressure down for
  a few reports *before* the tablet reports the button, right after a 3–5 ms report gap; on 2.14.0 that released the hold (134.65 s
  of the session) and, with Activation Distance 1000, it stayed up for the 370 ms the pen stayed down. It now holds. On that session
  this is the only event that changes.
- A fresh contact ends any settle window, so a button change or a range-entry gap while hovering never freezes the landing after it.
- `tools/td2csv.py --analog --no-gap` for Linux Tablet Debugger logs, whose bursty Deltas fake report gaps.
- With Analog Pen off, every recording replays exactly as on 2.13.0 / 2.14.0.

Settings: the **cp923** preset gets **Hold Time 300** (was 400). The one remaining hold cut in the session was a wobble 179 ms into a
hold at ~4600 (margin 0.89 with 400, 1.20 with 300); taps release 0.34 ms later on average (25 of 79, at most 3 ms). Drags whose end
starts between 300 and 400 ms now get the ×4 Hold Allowance there, so their release can come later: in the session, the end of the
button-1 hold released 91 ms later (10 ms before the lift instead of 101). Tap Allowance 0.4 instead would hold the wobble with the
same margin without that, at +1.3 ms on taps.

Not handled (firmware): the CP923 sometimes drops 50–230 raw for one report when a press rises through ~800 raw; that released 2 landings
in the session.
