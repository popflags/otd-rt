### Analog Pen toggle (CP923 on the PTK-670 custom firmware)

New settings, both off / unused unless **Analog Pen (CP923)** is ticked. With the toggle off, every recording replays exactly as on 2.13.0.

- **Analog Pen (CP923)** (default off): for the analog CP923 / Wacom One pen on the PTK-670 firmware (ring500 9f4a1b39). Turn it on
  while you use that pen, off for the Pro Pen 3.
  - Firmware Sample Clock counts **1.000 ms** per counter step (that pen steps it on every report) and adds the 2–5 ms report gaps
    of side-button changes, which the counter cannot see. Bursty delivery does not add time.
  - A side-button change steps the pressure (up to ~400 over ~10 reports). Those reports are taken as the new level, not as a release
    or a re-press. Lifts still release at once.
  - The phantom max-pressure check is off (this pen makes none), so a landing at 8191 presses on its first sample.
- **Button Settle Reports** (default 10): how many reports after a side-button change are taken as the new level. A real release in
  that time comes when it ends (up to ~10 ms later). 0 = only the report with the change.
- Firmware Sample Clock: after a mismatch with the host clock, the counter is trusted again when the pen changes (tool bytes), instead
  of never until the settings are re-applied. Its warning now mentions Analog Pen.
- Diagnostics CSV: new `buttons` and `gap` columns. `rt replay --set AnalogPen=true` uses the button changes;
  `tools/td2csv.py --analog` converts a CP923 Tablet Debugger log the same way.

Not handled: some button 1 presses lower the pressure by ~110 per report for 3–6 reports *before* the tablet reports the button,
which can still release a hold. Only the firmware can fix that without delaying releases.

Settings to update: none for the Pro Pen 3. With the CP923, tick Analog Pen (Firmware Sample Clock on as before).
